Limits of trust in model output

  • Fabrication → detectable by checking against sources
  • All other failure modes affect the user's judgement → not detected by checking single outputs
✦FabricationPlausible but false content, e.g. referencesdescription
  • Probable text ≠ correct text
  • Best-known case: invented references
  • Check: each reference against a catalogue

A language model generates text that is probable given the input; probability is not the same as correctness. Invented references can be detected by checking each reference against a catalogue or database.

▲HomogenisationSimilar structure across many textsdescription
  • Same system → same structure, register, examples
  • Visible only across a set of texts

Each text may be acceptable on its own, while a set of thirty submissions — or a set of module descriptions — shows little variation.

▲Illusion of consensusContested questions presented without the controversydescription
  • Disputed questions read as one coherent position
  • The disagreement is omitted, not denied

A summary of a disputed research question can read as a coherent position. The disagreement is not stated as absent; it is simply omitted.

▲Automation complacencyDecreasing verification over timedescription
  • After many correct outputs, checking gets weaker
  • Same error rate, fewer errors detected

After a series of correct outputs, users check subsequent outputs less carefully. The error rate of the system is unchanged; the proportion of errors that are detected decreases.

▲Confirmation and anchoringThe framing of the request shapes the answerdescription
  • Ask for reasons for → get reasons for
  • The first draft fixes the structure of later versions

A request for reasons why a method is appropriate yields reasons for it. A first draft sets the structure of later versions, including passages that are subsequently written by hand.

▲SycophancyAgreement with the user's positionevidence
  • Models tend to confirm the user's position
  • Warnings do not remove the effect (Chandra et al., 2026)
  • Checking with the same system is not independent

A hypothesis and its opposite, presented in separate conversations, can both be assessed favourably.

Chandra et al. (2026) model a conversation between a chatbot and an ideal Bayesian user who updates beliefs rationally. In the model, this user also develops unwarranted confidence, and the effect persists when the system makes no false statements and when the user is informed in advance that the system is sycophantic.

Effective countermeasures are procedural — a second reader, a request for counter-arguments, a source outside the conversation.

▲Learning stallOmitted difficulty, omitted learningdescription
  • The system does the effortful part
  • Finished work, unpractised skill

Where a system completes the part of a task that requires effort, the student submits finished work without having practised the underlying skill. The deficit becomes visible later, for example in oral examinations or in subsequent modules.

▲Embedded positionsOutputs reflect positions that were not chosendescription
  • Outputs carry positions on contested questions
  • Identify them in generated reading lists, questions, cases

Model outputs contain positions on contested questions of a discipline, on what constitutes a good argument and on which authorities are cited. When a system generates a reading list, a seminar question or a case study, the positions implied should be identified and assessed.

■DeskillingLoss of the judgement needed to evaluate outputdescription and evidence
  • Unused judgement declines
  • → the other failure modes go undetected
  • A structural problem: change the environment (Ferdman, 2026)

Evaluating model output requires domain judgement. If this judgement is no longer exercised because the system performs the task, it declines; the ability to detect the other failure modes declines with it.

Ferdman (2026) introduces the concept of a capacity-hostile environment: an environment in which the mediation of a system prevents a capacity from being developed. Individual resolutions are therefore insufficient. Effective measures change the environment: tasks that are deliberately not routed through a system, review steps signed by a person, and module designs in which the difficulty is part of the learning objective.

Lab 5Grounding: answers with and without a source3 min
  • Aim: can you tell a sourced answer from an unsourced one by reading?
  • Run A: question only · Run B: source + question
python -m llmlab lab ground

Background. A model's knowledge ends at its training cut-off. Grounding places the relevant source text in the prompt; retrieval-augmented generation (RAG) automates this step. Grounding reduces unsupported statements but does not eliminate them.

Materials. Question: "Under the EU AI Act, when do the obligations for Annex III high-risk systems begin to apply, and what is not deferred?" Source: a short text stating that Regulation (EU) 2026/1744 defers these obligations to 2 December 2027 and that Articles 4, 5 and 50 are not deferred.

Procedure. Run B adds the instruction "Answer using the source only. If the source does not settle the question, say so." Both runs use temperature 0 and seed 3. Both answers are searched for the year 2027; run A is also checked for an opening sentence that declines to answer.

▸AdministrationInstitutional platforms, licensed editions, open and local modelsoptions and limitations
  • Institutional: SURF EduGenAI, GWDG Chat AI, Open WebUI, HAWKI
  • Licensed editions: Copilot Chat, Gemini / NotebookLM for Education, ChatGPT Edu, Claude for Education
  • European / open: Mistral, Apertus, EuroLLM
  • Local: Ollama, LM Studio — no data leaves the computer

Institutional and national platforms. SURF EduGenAI (Netherlands) is a national pilot with open-source and commercial models, planned for general availability around the end of 2026 and not intended for assessment or fraud detection. GWDG Chat AI (Germany) is available through the academic cloud. Open WebUI and HAWKI are open-source front ends that an institution hosts in front of licensed models. Advantage: the contractual agreement and retention rules. Limitations: the available models change, so a prompt may behave differently from one term to the next, and the service requires operation by the institution.

Licensed education editions. Where an institution has concluded a contract, training on institutional data is excluded and administrators control retention. Limitations: the providers are based outside the EU, so data residency in the EU determines the storage location but not every question of access; terms change faster than institutional review cycles; dependence increases with every module built on one provider.

European and open models. Mistral (France), Apertus (Switzerland; ETH Zurich, EPFL, CSCS; Apache 2.0, trained on more than a thousand languages) and EuroLLM (EU-funded; all 24 official EU languages). Their composition is documented. Limitations: open models perform below the leading commercial models on demanding tasks and still require hosting.

Local models, as used by llmlab. Limitations: smaller models perform worse on long documents and in languages other than English, and computers without a suitable graphics processor are slow.

▸PreparationOutput is reviewed before it reaches studentsoptions and limitations
  • Task variants, worked examples, question banks, plain-language handouts
  • Low risk: the teacher reviews before use
  • Generating is fast — selecting and checking is not

Transcription. Open-weight speech models can transcribe recorded lectures locally. Error rates increase with technical vocabulary and regional accents, and some models generate text during silent passages.

Translation. An EU-based service such as DeepL is suitable for teaching material. It is not suitable for students' submitted work (see the copyright panel).

▲In-classStudents are present and cannot easily opt outoptions and one prohibition
  • Captioning / translation: an aid, not a record
  • Prohibited: emotion inference in education (Art. 5(1)(f))
  • Engagement scores used for assessment → evaluation tools

Live captioning and translation improve accessibility. Their quality decreases with background noise, unfamiliar accents and technical vocabulary; they should be announced as an aid and not used as a record.

Systems that infer emotions from faces, voices or posture in education are prohibited (see the legal panel). Attendance tracking, engagement scoring and participation analytics also belong to this area. Once their results are used to assess students, they become evaluation tools.

■EvaluationThe output affects a student's recordoptions and requirements
  • Rubrics: teacher designs, nobody is assessed
  • Feedback drafts: depends where the text is processed
  • Marking support: who decides? can the student contest?
  • Detection: see below

A grade is a decision about a person. Two questions follow: whether a person with authority takes the decision, and whether the student can contest it. For drafting feedback, the requirements depend on where the student's text is processed (see the copyright panel).

Publicly available tools and their conditions of use

  • Personal account = no institutional agreement (no processing agreement, no retention control)
  • OK: preparation with public material
  • Not OK: student work, personal data, unpublished research, anything graded
  • Three triage questions: Where is the text processed? Who agreed to what? What if the output is wrong?

Students and staff frequently use these tools with personal accounts. There is then no notification of changed terms either.

Lab 7Deployment route and legal obligations3 min
  • Aim: where were the requests processed?
  • Which obligations depend on the route — and which do not
python -m llmlab lab route

Background. llmlab sends requests over HTTP to a model server. With the default configuration the server runs on the same computer and is addressed through the loopback interface (127.0.0.1). A local route avoids a processor relationship under GDPR Art. 28 and third-country transfers; obligations under the AI Act (Art. 4, Art. 50, Annex III point 3) attach to the use of the system and apply regardless of where it runs.

Procedure. The endpoint of the active backend is read and checked for a loopback address; the JSON request format of the backend is shown; the obligations are listed by route.

Legal framework

Five provisions and one amended date

  • Art. 4 — AI literacy of staff · since Feb 2025
  • Art. 5(1)(f) — emotion inference in education prohibited · since Feb 2025
  • Art. 50 — transparency towards people · since 2 Aug 2026
  • Art. 14 — human oversight of high-risk systems
  • Annex III point 3 — education uses listed as high-risk
  • Reg. (EU) 2026/1744: Annex III obligations → 2 Dec 2027; Arts. 4, 5, 50 not deferred

Art. 4 AI Act — AI literacy. The deploying organisation, for teaching purposes the institution, takes measures to ensure sufficient AI literacy of its staff. Not deferred.

Art. 5(1)(f) AI Act — prohibited practice. Inferring the emotions of a person in the workplace or in education, except for medical or safety reasons. Not deferred.

Art. 50 AI Act — transparency. Persons must be informed when they interact with an AI system or receive certain artificially generated content. If a chatbot answers students' questions about a module, the deploying institution is responsible for this information.

Art. 14 AI Act — human oversight. Oversight must be exercised by persons who understand the system and are able to override its output; formal approval without these conditions does not meet the requirement.

Annex III point 3 AI Act — education. Admission and assignment to institutions, evaluation of learning outcomes, assessment of the appropriate level of education, and monitoring of prohibited behaviour during tests.

Amended date. Regulation (EU) 2026/1744 (Digital Omnibus on AI), published in the Official Journal on 24 July 2026 and in force since 27 July 2026, defers the obligations for standalone Annex III high-risk systems from 2 August 2026 to 2 December 2027, and for Annex I embedded systems to 2 August 2028. The stated reason is the delayed availability of harmonised standards. The content of the high-risk obligations is unchanged; only the date of application has moved.

GDPR Art. 22

  • No significant decision based solely on automated processing
  • A grade is a typical case
  • Human involvement must be meaningful

A data subject has the right not to be subject to a decision based solely on automated processing which produces legal effects concerning them or similarly significantly affects them. Meaningful involvement means that the person involved has the authority and the information to reach a different decision.

AI detectors

  • The main objection is not accuracy
  • It is the impossibility of disproof and the unequal distribution of errors
■Asymmetric consequencesThe two error types differ in severityargument
  • False negative → a grade too high
  • False positive → disciplinary proceedings, possibly residence status

A false positive can also damage the relationship with the department. An instrument with such unequal error consequences has to be assessed against this asymmetry rather than against an average error rate.

■No possibility of disproofThe accused student cannot demonstrate authorship conclusivelyargument
  • Drafts and version histories can be produced afterwards
  • No means of refutation → not a fair procedure

Version histories and drafts support a student's account but can be produced retrospectively. A procedure in which the accused person has no means of refuting the accusation does not meet the requirements of a fair academic-integrity procedure. See Bassett et al. (2026).

■Unequal distribution of errorsCorrelation with first languageargument
  • Detectors react to features of second-language writing
  • More false positives for students writing in a second language

Detector scores respond to short clauses, conventional collocations and low lexical variability. These are also features of competent academic writing in a second or third language. The students affected are often less able to contest an accusation. The instrument measures, in part, a different property from the one it is intended to measure.

Equity of access

  • Paid models perform better → an assessment may measure access
  • A tool the institution does not provide cannot be required
  • AI-assuming tasks are fair only with teaching and comparable access

The most capable general models are currently available in paid versions. If a task can be completed better with a subscription, the assessment partly measures access to paid tools, and this is not visible in the grades. Where the institution provides a compliant option, its timely availability is the relevant equity measure.

Copyright in students' work

  • Copyright belongs to the student
  • Uploading it = use of a protected work by the teacher
  • Anonymisation does not solve this
  • → institutional or local system only; state it in the module handbook

Copyright in examination scripts, term papers and theses belongs to the student. Uploading such work to a commercial assistant, for example to draft feedback, happens usually without the student's knowledge and frequently under terms that allow the provider to retain the text. This question is separate from data protection and is not resolved by anonymisation, because the protected object is the work itself. Any intended use of an external service is stated in the module handbook before submission.

Resource consumption

  • Every inference costs energy, water and hardware
  • Use the smallest model that does the task
  • Batch inputs; store answers instead of per-student calls
  • Lab 7 shows where the consumption occurs

Consumption occurs regardless of whether the output is used. In teaching materials that are opened by every student of a cohort, avoid calls to hosted models where a stored answer would suffice. The processing route reported by Lab 7 determines where the consumption occurs.

Automated feedback

  • General feedback: safe, but changes nothing
  • Specific feedback: useful, but needs reading the work
  • → draft with a skill prompt, review before release

Krommer (2026) describes automated feedback as a choice between two problems. Feedback general enough to be generated without risk is too general to change students' work. Feedback specific enough to change students' work has to be defensible in every sentence, which requires reading the work. A defensible use therefore consists in drafting feedback with a documented standing instruction (a skill prompt, Block 3) and reviewing the draft before it is released to the student.

Agents and online tests

  • Agents can open course pages, answer and submit tests
  • Unsupervised online tests no longer show who answered
  • Formats where the working process is the evidence help

AI agents can open course pages and PDF files, answer questions and submit forms. Practitioner reports describe this in regular teaching. Detection and extended honour codes do not address the problem. The design of process-based formats is beyond the scope of this session.

Six terms and their consequences for teaching
TermIn shortError if ignored
Tokenthe unit a model processesGerman or Polish need more tokens than English

Token. A word, part of a word or a punctuation mark from a fixed vocabulary. Text volume is often estimated in pages rather than tokens. The same sentence requires more tokens in German or Polish than in English, which affects cost, processing time and the usable context.

Context window. The maximum number of tokens processed in one request, including instructions, documents and answer. A 90-page thesis is summarised, and the summary is taken to cover the whole document. Text beyond the window is removed before processing, and the answer does not indicate this.

Training vs inference. The model parameters are fixed during use. Corrections in a chat are assumed to be learned, so they are repeated instead of being written into a standing instruction. Where a system appears to remember, it reads stored text back into the prompt (memory, or a wiki at stage 5).

Grounding. Whether the answer was generated with the relevant source text in the prompt. The wording does not reveal whether a source was used; only comparison with the source does.

Temperature and seed. Temperature determines how the next token is sampled; the seed makes sampling repeatable. Otherwise two identical scripts receive different comments, and neither can be reproduced when a grade is contested.

Deployment route. Own computer, institutional server or external provider. A local route removes the processor relationship; Annex III, Art. 50 and Art. 4 still apply.

The five stages of prompting

The stages do not indicate output quality. They differ in what is retained, how many steps run without intervention, and which artefacts require review.

Example used for all five stages: replies to student emails

  • Fictitious module EDU-204 Research Methods in Education, seven emails
  • Most: answerable from the module information
  • Extensions and grades: examination office decides
  • Requests about other students: not answered

The example is suitable for all five stages because it involves many similar inputs, a reference document, rules whose violation has consequences, and cases that must be decided by a person.

Inbox: 01 date of the written exam · 02 extension request due to illness · 03 availability of slides (not covered by the module information) · 04 reading list and office hours, in German · 05 request to raise an exam grade · 06 question about a flatmate's exam registration · 07 question on the sample size of a portfolio study.

①Stage 1 — PromptA single request in a chat windowapplied to the example
  • Email 02 + "Answer this email:"
  • Typical: promises the extension, invents dates
  • Fine for one-off tasks; nothing is retained

No instruction, no module information. The model has no information on who decides extensions and no dates. Replies frequently promise the extension ("We will extend your deadline by one week") or state dates not contained in any source. Corrections made in the conversation are not retained for the next email.

②Stage 2 — Skill promptA stored instruction with rules and reference documentapplied to the example
  • System prompt = ten rules + module information
  • Written once, reviewable, reusable
  • Most useful stage for most teaching staff
  • No systematic checks, no record

The ten rules: use only the sources; a fixed sentence for open questions; no decisions on extensions or grades; no information about other students; no identifiers; language of the email; salutation and signature; 150 words; answer the question asked; copy names of courses, folders and rooms exactly. Each email is pasted individually.

Stored instructions exist as custom instructions, custom GPTs and Gems, and as SKILL.md files in agent tools (published as an open standard in December 2025). This stage does not record which reply was produced with which instruction.

③Stage 3 — HarnessA program applies fixed steps to a folder of emailsapplied to the example
  • Classify → draft → write file with provenance → route
  • ready/ or review/ by category only
  • Traceable, but replies are not checked

For each email in the folder the program (1) sends a classification request that assigns one of five categories — information, extension, grade, third_party, other; (2) sends a drafting request with the handling rule for that category and the system prompt from stage 2; (3) writes the reply to a file whose header records input, category, route, model, settings and time; (4) places the file in ready/ or review/. third_party and other always go to a person.

A harness is justified when the same procedure is applied to many inputs and has to be documented. Because replies are not checked, a reply in an automatic category can be placed in ready/ although it violates a rule.

④Stage 4 — LoopChecks, revision and a stop conditionapplied to the example
  • Nine automatic checks per draft
  • Failed checks → revision request
  • ready/ only if all checks pass
  • Checks are text patterns, not proof of correctness

The nine checks: salutation, signature and a closing in the reply's language; word limit; at least one content word of the subject line occurs in the reply (automatic categories only); every date occurs in the module information, an approved answer or the email; every quoted name occurs verbatim in the sources; no sentence with "I/we" and a verb such as grant, extend, change, raise without negation; examination office named (for extension and grade); language of the email; no matriculation number.

Failed checks are returned to the model with the email, the draft and the rule concerned. The loop stops when all checks pass, when the reply contains the sentence for open questions, or after the maximum number of rounds. A reply is placed in ready/ only if all checks pass, the category is automatic and no open question remains. A reply can pass the checks and still be wrong, and a correct reply can fail them. Each round is an additional inference.

⑤Stage 5 — WikiA file that is read before and extended after each runapplied to the example
  • wiki.md: lessons · open questions · approved answers
  • Approved answers are written only by people
  • The model doesn't change — the file does
  • Whoever edits the wiki shapes every later reply

Lessons from failed checks — written by the program: one line per rule that first drafts violated, added to the instructions of later runs. Open questions — written by the program: emails that the sources could not answer (in the example, email 03 on slides). Approved answers — written by people, for example "The slides for each session are uploaded to the learning platform by 18:00 on the day before the session." Later runs use approved answers as a source; in the next run email 03 is answered and, if all checks pass, placed in ready/.

The process thus handles a growing share of emails without intervention, while decisions remain with the examination office and sensitive categories with a person. Errors in the wiki are repeated, and personal data must not be entered. Karpathy's LLM wiki (2026) describes this pattern; the memory functions of commercial assistants follow the same principle without making the stored text visible.

3.4 · Example of a specified teaching artefact

  • Developed at OvGU from a written specification
  • Publicly available

Circular construction safety and material twin

  • Browser simulation for vocational construction education
  • Live weather, eight sensor channels, six material passports
  • Learner output: diagnosis, action, written justification
  • No server, no API key

The simulation combines live regional weather data, a fault developing across eight sensor channels, three consultations with different roles and six material passports. Learners route materials to reuse, repair, recycling or quarantine; retained mass, avoided carbon emissions and avoided replacement costs are shown against a circularity score. The application runs on a static web host.

Required competences and three design decisions
LiteracyFunctionConsequence if absent
Programming — readingUnderstanding the project structure, running it locally, checking and publishing it.The output cannot be checked and has to be trusted.
Programming — architectureDeciding in advance against a server, keys and a database, based on the obligations each would entail.A generated architecture is accepted, and its data protection consequences become apparent afterwards.
Prompting — specificationStating constraints, data provenance rules and the pedagogical objective.A generic result that takes longer to correct than a specification would have taken to write.
Prompting — iterationDeveloping in small, versioned steps that can be reviewed and reverted.One large request and one large result that cannot be reviewed.
  • Architecture: no login, no accounts, no server storage → no personal data
  • Provenance labels: live, virtual and estimated values are marked
  • Decision record: diagnosis, action, justification — timestamped, assessable

1 · Architecture and data protection. Learners' decisions remain in the browser. The only external request retrieves public weather data and transmits no personal data.

2 · Labelling of data provenance. Weather values are labelled as live external data; concrete, strain, crane-tilt, dust and electrical channels as virtual until physical sensors are connected; impact figures as educational estimates. Learners know the provenance of every value on which they base a decision.

3 · Output as a decision record. Diagnosis, action and written justification form a timestamped process artefact suitable for assessment.

Purpose and maintenance

  • Which teaching problem does it solve that a seminar does not?
  • What does it replace rather than add?
  • Who maintains it?

These three questions should be answered in writing before a further artefact of this kind is developed. An artefact that is not maintained cannot be used as an open educational resource in the long term. Where substantial parts were generated, credibility depends on a public record of contributions (who, what, which commit, which date); a repository provides this by default, a file sent by email does not. If the artefact is a fork, the relationship to the original is stated on the repository page.

Transfer to other disciplines

  • Pick a situation students cannot practise for real
  • Specify constraints · build in small versioned steps · label real vs simulated data
  • Assess a justification, not a score

Suitable situations are those where the real setting is dangerous, slow, expensive or rare. Examples include welding, clinical triage, laboratory safety, negotiation, network incident response and ward handover.

Legal classification of the example

  • No personal data → no data protection requirements
  • Annex III applies once the score contributes to a grade
  • Art. 50: generated responses are labelled · Art. 4: staff can explain the tool

No learner is evaluated with consequences for their studies, so Annex III point 3 does not currently apply. Art. 50 applies to what learners are told: generated consultation responses are labelled as generated. Art. 4 concerns the staff who deploy such tools and are required to be able to explain them.

3.5 · Three positions from the literature

◆AI as an instrument of reflectionA stage-2 instruction for student writingdescription
  • Examine the draft instead of improving it
  • The student remains the author

The instruction asks the system to state the claim of a paragraph, list the conditions under which the claim holds, and identify which of these conditions the text does not establish. The student receives questions that a supervisor would ask (ZHQ, FH Aachen, 2026). As a stored instruction this is a stage-2 artefact that a programme team can adopt, discuss and revise.

◆Academic writing as a process of thinkingWampfler (2026)argument
  • Writing forms thought, it doesn't transcribe it
  • Which parts must students do themselves? → assessment design

Wampfler (2026) argues that the debate rests on the assumption that academic writing transcribes finished thought, which makes its automation appear either harmless or fatal. If writing is instead the process in which thought is formed, both positions are untenable. The relevant question can be answered for a specific module, and the answer determines the assessment design.

▲AI-generated companion materialLehrwende (2026)observation
  • Does the material say what to do in practice?
  • Are generated parts identifiable?

A German-language book on higher education in the age of generative AI is accompanied by slides and podcast episodes that are entirely AI-generated. A note circulated in the OvGU working group observes that this material shows the typical weaknesses of such material and that concrete recommendations are rare. The two criteria above apply to any material, including this session.

Verification tools

  • Fabricated references are a measurable trend
  • Verification tools have their own errors and data routes
  • → document them in the decision record too

Reference verification services and research tools for detecting citation hallucinations have appeared. Under Art. 4 they, too, have to be understood by those who use them, so they are documented together with the tool whose output they check.
